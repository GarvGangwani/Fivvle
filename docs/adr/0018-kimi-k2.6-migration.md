# ADR 0018: Kimi K2.6 Migration via Moonshot Direct

## Status

Accepted — 2026-06-01. Implemented in commits 85ebeba, cb4429a, ce80d1a, 98e8dce. All 5 pipeline phases on `kimi-k2.6`.

## Context

Sonnet 4.6 baseline: $1.34 mean / $1.54 P90 per ValidationReport across N=6 calibration ideas. Founding team approved migration to Kimi K2.6 for cost reduction. ADR 0014 prompt-caching already in place. Reader quote-guard hardened in ADR 0017.

Prior Haiku attempt (2026-05-27) failed: schema max_length caps tuned to Sonnet broke under Haiku verbosity. Lesson: any model migration requires per-phase recalibration evidence, not a config flip.

## Decision

Migrate all 5 pipeline phases (refinement, planner, reader, reflector_query, synthesizer) to `kimi-k2.6` served via Moonshot direct API (`https://api.moonshot.ai/v1`, OpenAI-compatible). New `kimi` provider in single LLM wrapper.

## Hard Constraints (discovered via smoke testing)

- **Thinking mode MUST be disabled** for structured output. Instructor's tool_choice='specified' is incompatible with Kimi's default thinking mode (Moonshot returns 400). Adapter forces `extra_body={"thinking": {"type": "disabled"}}` on every Kimi call.
- **Temperature MUST be exactly 0.6** when thinking is disabled. Moonshot rejects any other value with HTTP 400 ("invalid temperature: only 0.6 is allowed"). Adapter overrides whatever the caller passes; per-phase temperature config (Synthesizer 0.3, etc.) is ignored for Kimi.
- **Empty system message MUST be dropped**. Planner uses Anthropic prompt-caching pattern where `PLANNER_SYSTEM_PROMPT = ""` is empty by design (cacheable content lives in `user`). Anthropic accepts empty system; Moonshot rejects with HTTP 400. Adapter conditionally drops empty system entries from messages list for Kimi only.

## Known Trade-offs

1. **Quote fidelity regression.** Kimi paraphrases verbatim quotes more loosely than Sonnet. In N=6 calibration, 4/6 ideas had at least one Reader question hit `quote_hallucination_rate exceeded` (>10% threshold); worst case tax-loss q1 at 33%. ADR 0017 near-match guard recovers many, but genuine quote drift gets nulled — evidence is lost. Citation count down 21% partly reflects this. Pipeline still passes READY because guard preserves correctness over completeness.
2. **No per-phase temperature variation.** All Kimi calls at 0.6; cannot tune Synthesizer to lower temp for less drift (was 0.3 on Sonnet). Acceptable per calibration but limits future tuning.
3. **Latency +20%.** Within usable range for ~7-min Deep Research UX; not a blocker.
4. **Cost composition shift.** Kimi LLM share dropped to ~$0.11/run (19%); Tavily searches now ~$0.48/run (81%). Future cost reduction work targets query count, not LLM choice.

## Tavily Cost (informational)

Per all-Kimi N=6 eval: ~30 Tavily calls/run × $0.016 = ~$0.48. Driven by planner (7 questions × 3 queries = 21) + reflector re-searches (~9). Lever for further savings: prompt the planner toward fewer/tighter queries.

## Pricing Reference

Kimi K2.6 via Moonshot direct (verified 2026-06-01):

- Input (cache miss): $0.95 / 1M tokens
- Input (cache hit): $0.16 / 1M tokens
- Output: $4.00 / 1M tokens

Compared with Sonnet 4.6: ~3× cheaper input, ~3.75× cheaper output.

Moonshot prompt-caching not yet modeled in `cost.py` (uncached rate used for all entries; conservative). Future work: model cache hits to track actual cost vs theoretical floor.

## Revert Path

Whole-branch revert, NOT cherry-pick. If reverting Kimi, revert the *entire* migration commit chain (85ebeba, cb4429a, ce80d1a, 98e8dce) so model strings AND adapter constraints AND pricing entries unwind together. A partial revert (e.g. flipping `.env` back to Sonnet while leaving the wrapper's Kimi-forced-temp-0.6 path in place) is benign because the wrapper branches on provider, but the calibration evidence (this ADR's table) becomes stale.

To revert just the model without removing the adapter (e.g. for a single experiment), set in `.env`:

```
synthesizer_provider=anthropic
synthesizer_model=claude-sonnet-4-6
...repeat for each phase
```

The Kimi adapter stays in place, dormant. Calibration caps (none changed for this migration — Kimi was conservative enough that no `max_length` widening was needed) remain compatible with Sonnet.
